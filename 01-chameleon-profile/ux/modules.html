UX · DETAIL 05 · THE MODULE LIBRARY

Nineteen building blocks.

A profile isn't a template — it's an assembled kit. The Chameleon picks from 19 modules across 5 groups; required modules anchor every profile, optional modules load per archetype default, and opt-in modules surface only when a Chameleon explicitly wants them. Each module has variants — a single "Bio" module can be long-form for a Strategy archetype or short-personal for a Creative. This page catalogs every module, every variant, and which archetypes each is built for. Wireframes show the canonical visual; the spec tables show the rules.

FIVE GROUPS · NINETEEN MODULES · INFINITE PROFILES

The kit, not the template.

The Module Library is the spec for what's possible on a Chameleon profile — not what's mandatory. Required modules anchor every profile so we don't ship half-built pages. Optional modules load per archetype default so a Strategy archetype doesn't have to delete the Metrics Cards every time. Opt-in modules surface only when a Chameleon explicitly wants them, so the profile doesn't read as a template by default.

Variants are the second layer of flexibility — the same Bio module can be long-form for Strategy or short-personal for Creative, and the CC Intelligence layer can swap variants per visitor context (an incoming healthcare brief gets the Healthcare bio variant). Modules + variants together mean a single library spec produces every archetype's profile shape without bespoke design work.

All 19 modules are now wireframed. Each one connects back to Chameleon Admin for the editor surface, Profile Expressions for how modules render in Card/Bio Module/Pill contexts, and Wireframes for the three structural directions (Editorial, Active Pitch Tool, Live Page) that govern how modules stack on the profile page.
