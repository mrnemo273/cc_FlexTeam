UX Architecture · Detail 03

Search & Discovery.
The cold-inbound front door.

If Smart Deliverable is how BD warm-pitches a known client, Search & Discovery is how an unknown client finds a Chameleon for the first time. Four entry modes — conversational AI search, traditional filter UI, external SEO/GEO surfaces, and Chameleon-controlled curation — all funnel into the same Profile. This page wireframes each mode and shows how the four interact.

Flow — four front doors, one destination
01
FRONT DOOR · ON-SITE · CONVERSATIONAL · MOBILE-FIRST

"Describe what you need."

A chat-style front door that lives on the Chameleon Collective website — not a separate app, not a separate page. A floating prompt sits at the bottom of the homepage; when a client taps it, the chat takes over the viewport, but the CC logo and website framing stay on top (close × returns home at any time). The client types or speaks a brief in plain English; CC Find replies with a short answer and emits interactive match cards inside the thread — a hybrid between a conversation and a search result. Refinements happen as tappable chips or follow-up questions. Mobile-first, because clients live on their phones. This is how Round 1 voices kept describing what they wanted — Idea 15.

Used by
Cold inbound clients · clients who've described what they need before knowing CC's structure
Index inputs
Curated tags · semantic embeddings of bios & case studies · industry crossover · availability
Replaces
The Leaders / Delivery Specialists / Recruiters filter chips that don't match how clients actually search.
Learns from
Which result the client clicked · which refine chip they tapped · which Chameleon they ended up booking with
02
FRONT DOOR · STRUCTURED FILTERS

For clients who know what they want.

Structured filter UI for the two scenarios Round 1 surfaced — practice area browse (client lands on a practice page and wants to see who's available there) and industry-specific deep search (client searches at the intersection of capability + industry). Filters are sortable, multi-select, persist in URL so results are shareable. Replaces the current category chips that don't match how clients actually search.

Two flows
Practice browse (start on a practice page) · deep search (start with capability + industry filters)
Filters
Capability · Industry · Availability · Tenure · Location (collapsed) · Archetype (collapsed)
URL behavior
All filters persist in URL · shareable · bookmarkable · BD can send a pre-filtered link
Results format
Profile · Card expression (3-column grid by default) · 6-9 visible · load more on scroll
03
EXTERNAL · SEO + GEO

Findable from outside the site.

Most cold inbound starts on Google or in an AI chat — not on chameleoncollective.com. So every Profile needs to be readable by both search engines (SEO) and generative engines (GEO). The structured data the system already holds becomes Person + FAQPage + Article schema; AI engines pull from those schemas to answer questions like "best fractional CMOs for healthcare." Wireframe shows the same Profile rendered three ways: as Google search result, as Perplexity citation, as Google AI Overview snippet.

Why this matters
~60% of cold inbound now starts with an AI engine query, not Google search. GEO is the new SEO.
Auto-generated from
Every field in the Profile repository → corresponding schema property. No manual SEO work per Chameleon.
Updates
Real-time. Availability change → schema updates → next crawl reflects new state.
Measured by
Impressions, click-through, AI-engine citation events, attribution back to bookings.
04
CHAMELEON-CONTROLLED · CURATION

You shape your own findability.

What the Chameleon controls in their own admin panel about how findable they are. Curated skill tagging (Idea 23) replaces tag walls with 3–7 hand-picked tags that read as confidence, not padding. Each Chameleon also gets a real-time Findability Score showing how their Profile reads to each entry mode, and AI-suggested tags pulled from their actual project history.

Lives at
admin.chameleoncollective.com/me/findability
Updates from
Tag edits · project additions · content claims · LinkedIn pulls · BD-side activity
Replaces
The 50-tag wall in COS that signals padding, not specificity
Connects to
All four entry modes · Routing tier from Idea 14 · Curated tagging from Idea 23
What this enables · what's next

With the Profile and its expressions, the warm-pitch flow, and the cold-inbound front doors all in place, the system has both inbound paths covered. Decision 002 (search re-architecture) and Ideas 15, 16, 23 all converge here. The Chameleon's findability is now controllable, measurable, and present across every channel a client could plausibly start from.
