UX Architecture · Detail 02

The Smart Deliverable Creator.
The warm-pitch flow.

A live, tracked link that replaces the bio slide. BD drops a brief, the system surfaces the right Chameleons, bios get auto-tailored, JCM (or whoever) reviews and sends. The client gets a single URL that holds 1–N Chameleons all tailored to their ask. Every open, dwell, and click feeds back to BD. The flagship Phase 1 build — promoted to Decision 008 in the stakeholder pass.

Flow — brief in, live link out
01
CLIENT-FACING · THREE USE CASES

The client sees a live, tracked link.

Three patterns covering 95% of warm-pitch situations. A is the canonical shortlist (most common). B is the single-Chameleon deep-dive (when you're pitching one specific person). C is the build-a-team (multi-discipline assembly). All three share the same deliverable shell — tailored header, Bio Module stack, footer analytics tag. They differ in what gets stacked.

A
USE CASE A · CANONICAL SHORTLIST

3 CDs for a healthcare CMO role.

The classic warm-pitch: client asks for N options, BD sends N tailored bios in a single live link. Client compares, picks one, books. Every Chameleon in the deliverable can see they were on it.

B
USE CASE B · SINGLE-CHAMELEON DEEP DIVE

One Chameleon, the full pitch.

When you're pitching one specific person for one specific role. The deliverable becomes a richer profile — Bio Module on top, extended context below (relevant case studies, project deep-dives, additional testimonials, scheduled meeting CTA).

C
USE CASE C · BUILD-A-TEAM

Multi-discipline shortlist by role.

When the client needs a whole team. Bio Modules grouped by role — CDs, Designers, PMs. Client picks one from each section. Sections collapse/expand. The deliverable becomes an interactive build flow.

Shared shell
Browser frame · tailored header (client + role + sender + expiration) · live link · analytics tag in footer
What varies
A: stacked Bio Modules · B: Bio Module + extended context · C: grouped by role + selection state
Per-pitch edits
Header copy · bio tailoring · experience card emphasis · expiration window · additional case studies in B
Replaces
The Google Slides bio + email PDF workflow. Decision 006 (PDF deprecated) and Decision 008 (Smart Deliverable is Phase 1) both land here.
02
BD ADMIN · CREATION FLOW

BD assembles in one structured hour.

Brief in, deliverable out. The system surfaces fits, handles Slack opt-in coordination, auto-tailors the bios, queues them for BD to review and approve. JCM's half-day of Slack DMs collapses to a single dashboard view. Wireframe shows the dashboard at the "ready to send" stage — brief loaded, fits surfaced, 3 of 4 Chameleons accepted, bios tailored and awaiting approval.

Lives at
admin.chameleoncollective.com/deliverables/new · BD/CSM access only
Replaces
The BD-posts-to-Slack scramble. Five DM threads → one structured queue. D-07 retires the raise-hand model.
Time-to-send
~45 min from brief to live link (vs. half-day with old workflow). Most of the gap is Chameleon Slack response window.
Privacy
All match scores + decline reasons visible to BD. Chameleons see their own match status & current pitches per Idea 29.
03
POST-SEND · TRACKED

Every move is measured.

After the link goes out, BD watches the engagement come back. Which Chameleon's bio did the client open first, which one did they dwell on, which sections of which bio got read. The system learns what closes — and the Chameleon sees their own analytics on their Profile · Admin too. The single biggest gap the old PDF workflow had.

Visible to
BD / CSM (full view) · each Chameleon (their own row + their own bio heatmap) · not the client
Closes the loop
The system learns what closes — which bio framing, which experience cards, which capability emphasis converts. Feeds back into auto-tailoring for future briefs.
Replaces
The PDF black hole. Old workflow: send and pray. New workflow: send, watch, learn.
Privacy
Client identity anonymized to other Chameleons (Caleb sees "Acme CMO pitch" — not "the deal Nemo won"). Match-score reasoning visible only to BD.
What this enables · what's next

The Smart Deliverable Creator is the warm-pitch surface that the rest of the system orients around. With it shipped: BD doesn't scramble in Slack; Chameleons see the deals they're on without asking; clients get a tracked link instead of a stale PDF; the system learns what actually closes. Decision 008 (Phase 1 build), Decision 006 (PDF deprecated), and Decision 007 (raise-hand model retired) all converge here.

Next detail: Search & Discovery — the cold-inbound flow that brings clients to a Profile in the first place. Conversational + traditional + SEO/GEO + Chameleon curation. Now live.
