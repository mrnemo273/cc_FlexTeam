The first cut of wireframes proposed three structural directions — Editorial, Active Pitch Tool, Live Page. Reviewing the feedback, a sharper read emerges: Chameleons don't fit one shape, and they shouldn't have to. A strategist's work shows up differently than a designer's. An interim leader's case studies look nothing like an operator's. The right answer is a kit of modules with archetype-aware defaults — not three rigid presets.

The shift — from directions to modules

The three structural directions are useful as illustrative bundles of what a profile could feel like. But locking the Collective into one of them would force every Chameleon into a shape that doesn't fit their practice. The modular approach keeps the strategic commitments (feel consultancy, work talent network) while letting each profile match the work it's describing.

What stays the same

  • The eight-module page architecture as the canonical structure
  • Master + tailored children as the data model (Idea 26)
  • Multi-format output — web and slide/PDF from one source (Idea 27)
  • Four-tier opt-in lead routing (Idea 14)
  • Automated post-engagement testimonial collection (Idea 29)
  • The framing principle: feel consultancy, work talent network

What changes

  • No single “default profile” — defaults vary by Chameleon archetype
  • Each module has variants (visual / metric / narrative) that match the work it's showing
  • Modules can be reordered within their section group
  • Conditional modules appear only when relevant data exists (no half-built sections)
  • Admin becomes the central UX — Chameleon picks their starting kit, then refines
  • Adding new modules later doesn't require redesigning the page

The four Chameleon archetypes

Every Chameleon picks a primary archetype during admin onboarding. Their archetype loads sensible default modules; they can swap, add, remove. Archetypes aren't rigid categories — they're a sensible starting kit. Many Chameleons span two (Ivonne: creative + strategy; Ilan: operator + leader). The system supports that — but the default has to start somewhere.

On hybrids
Some Chameleons cleanly fit one archetype. Many span two (Ivonne, Ilan, Farzana — flagged above). The system handles this in two ways: (1) the Chameleon picks a primary archetype for default modules + content cadence, then (2) adds one or two modules from a secondary archetype (e.g., Ivonne starts as Strategy + adds the Visual carousel). The master + tailored children architecture means they can ALSO generate per-pitch variants that lean one way or the other depending on the client.

Reading the kits
The signature modules tell the truth about how each archetype's work shows up. Creatives lead with availability + sample carousel + peer endorsements + build-a-team — their value is being chosen for the next project. Strategists lead with bio + practice areas + narrative + thought leadership — their value is the body of thinking. Operators lead with stats + AI-tailored bio + metrics-forward cards + full contact form — their value is the demonstrated lift, and they're the ones most likely to pitch actively. Leaders lead with leadership stats + engagement timeline + executive testimonials — their value is the engagements they've led and the outcomes they own.

On the design choices
Each comp commits to one accent per page (per the cc-design-system rule). Orange repeats on Caleb and Ilan because both are leadership-coded archetypes — but the layouts differ dramatically (Caleb is editorial-magazine, Ilan is executive-boardroom). The variety across the four comps demonstrates that the modular system and the design system together can deliver distinct character per archetype without sacrificing brand consistency.

The admin — coming next

The module library and archetype kits change where the central UX lives. With three rigid directions, the design conversation is “which template?” With modules, the conversation becomes “what does my admin look like?” — because that's where Chameleons pick their archetype, swap in modules, configure their routing tier, manage tailored child profiles, and toggle automated testimonial collection.

This is the next workstream. The admin wireframe will visualize:

  • Archetype picker at first-time onboarding — “You're a Strategist? Here's your starting kit.”
  • Module library browser — drag-to-add, drag-to-reorder, all with strong defaults
  • AI-tailored bio flow — Jeff's manual workflow built native (Idea 25)
  • Master + tailored children manager — saved versions per pitch (Idea 26)
  • Routing tier selector — pick 1 of 4 with implications described per tier (Idea 14)
  • Automated testimonial collection settings — cadence, who gets asked, moderation queue (Idea 29)
  • Multi-format export controls — web + PDF/slide preview (Idea 27)

The strategic point: the admin is where the Collective's “feel consultancy, work talent network” promise is operationalized for the Chameleon. Get the admin wrong and even the best public page can't make up for friction. Get the admin right and the system maintains itself — which is the whole point.

Earlier explorations — three structural directions

The first cut of wireframes proposed three structural directions. We're preserving them here as project memory — they helped us see that the right answer wasn't any single one of them, but the modular approach above. Each direction now reads as a coherent bundle of modules — useful as an illustrative grouping but not the final architecture.

Direction A — The Editorial

  • Mapped to: Strategy + Voice archetype
  • Bundle: Editorial Hero + Long Bio + Narrative Projects + Activity Stream + Pull-Quote Testimonials + Light Contact
  • Useful as: the default starting kit for strategists, brand practitioners, voice writers

Direction B — The Active Pitch Tool

  • Mapped to: Operator + Growth archetype
  • Bundle: Stat Hero + AI Bio + Expertise Chips + Metrics Cards + Auto Testimonials + Tabbed Activity + Full Contact
  • Useful as: the default starting kit for performance practitioners, growth marketers, CROs

Direction C — The Live Page

  • Mapped to: Creative + Visual archetype (and looking-for-work mode for any archetype)
  • Bundle: Status Bar + Hero + Embedded Contact + Visual Carousel + Short Bio + Metrics + Peer Endorsements + Build-a-Team
  • Useful as: the default starting kit for creatives, designers, anyone with active capacity to fill

In other words: the three directions weren't wrong — they were templates. The modular system above generalizes them into a library where Chameleons can sit cleanly inside one bundle, or assemble across two when their practice spans both.

What's next

The modular approach reframes the design problem in a way that's honest to how Chameleons actually differ. Two parallel workstreams now make sense:

  • Round 2 testing of the modular approach — show the archetypes + module library to the Feedback Committee. Test: does your archetype fit you? Are there modules missing? Does the default kit feel like a good starting point?
  • Admin page wireframe (queued — see Section 08 next iteration) — design where the Chameleon picks their archetype, swaps modules, configures routing, manages tailored children, sets testimonial cadence. The admin is the central UX once the public page is modular.
  • One full BW wireframe per archetype kit — once we lock the modules, build a low-fidelity assembled-page wireframe for each archetype so we can see what the full assembled experience looks like. (Round 3 of this page.)

The strategic point hasn't changed: the profile is the moment our model becomes real to a client. The modular approach is how we deliver on that promise across the range of Chameleon practices, not just one of them.
